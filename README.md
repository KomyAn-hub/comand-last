Метою практичної роботи було набуття навичок використання сучасних технологій **Flexbox** та **CSS Grid** для розробки структури багатосторінкового, повністю адаптивного веб-сайту «Інфопортал». 
В ході роботи було розроблено загальну структуру сайту, включаючи Хедер, Футер та шаблони для сторінок «Головна» , «Новини»  та «Про нас» , які були стилізовані за допомогою CSS стилів.

Для організації верхньої частини сайту (`.site-header`) та внутрішнього вмісту навігаційного меню використано **Flexbox**, що дозволило легко вирівняти логотип і пункти меню,
а також реалізувати функціонал мобільного «меню-бургера» (за допомогою `script.js`). Основна частина контенту на Головній сторінці (`.content-wrapper`) також використовує **Flexbox**
для створення двоколонкового макета: сітка новин та сайдбар. При цьому сама сітка новин (`.news-grid`) реалізована за допомогою **CSS Grid** (`grid-template-columns: repeat(3, 1fr)`), 
що забезпечило її гнучкість і легкість адаптації. У Футері (`.site-footer`) застосовано **CSS Grid** (`grid-template-columns: 2fr 1fr 1fr 1.5fr`) для формування багатоколонкової інформаційної структури. 
Адаптивність забезпечена за допомогою **медіа-запитів** (`@media (max-width: 768px)`), які динамічно змінюють Flexbox-напрямки та Grid-шаблони (наприклад, з 3-х колонок на 1 колонку) для мобільних пристроїв.

Відповіді на Контрольні Питання

1.  У чому різниця між Flexbox і Grid?
    Основна різниця полягає у вимірності: **Flexbox є одновимірним інструментом** і призначений для впорядкування елементів або лише по горизонталі (рядку), або лише по вертикалі (стовпцю), фокусуючись на розподілі простору та вирівнюванні компонентів. На противагу цьому, **CSS Grid є двовимірним інструментом**, який дозволяє контролювати розташування елементів одночасно по рядках *і* колонках, створюючи складні макети сторінок та сітки.

2.  Коли доцільніше використовувати Flexbox, а коли Grid?
    Flexbox доцільно використовувати для внутрішніх компонентів, які потребують вирівнювання вздовж однієї осі, наприклад, для навігаційного меню,
     елементів картки (заголовок, зображення, опис) або форми. CSS Grid слід використовувати для побудови загального макета сторінки
    (основна структура layout, як-от хедер, сайдбар, футер) або складних сіток, де необхідно точне двовимірне позиціонування елементів, що перекривають кілька рядків чи колонок, як у нашому `.news-grid` або `.footer-content`.

4. Як задати вирівнювання елементів по вертикалі у Flexbox?
    Вирівнювання елементів по поперечній осі (яка за замовчуванням є вертикальною, якщо `flex-direction: row`) у Flexbox задається властивістю `align-items` на Flex-контейнері.
   Найчастіше використовують `align-items: center;` для центрування або `align-items: stretch;` для розтягування. Якщо ж контейнер має `flex-direction: column` (вертикальний потік),
   то вертикальне вирівнювання контролюється властивістю `justify-content`.

6.  Як працюють шаблони `grid-template-columns` та `grid-template-areas`?
    Властивість `grid-template-columns` працює шляхом визначення кількості та ширини колонок у Grid-сітці.
     Наприклад, `grid-template-columns: 1fr 200px 1fr;` створить три колонки, де середня має фіксовану ширину 200px, а дві крайні займають рівні частки (`1fr`) простору, що залишився.
    Властивість `grid-template-areas` дозволяє створювати макет сторінки, візуально позначаючи області комірок сітки за допомогою імен,
    які були присвоєні дочірнім елементам через властивість `grid-area`. Це робить код макета дуже наочним, дозволяючи швидко змінювати розташування блоків, просто переписуючи шаблонні рядки на контейнері.

8.  Як організувати спільну роботу з Git і уникнути конфліктів під час злиття?
    Організація спільної роботи з Git вимагає дотримання кількох ключових практик.
    По-перше, необхідно завжди працювати в окремих гілках (Feature Branches), ніколи не комітячи безпосередньо в основну гілку (`main`/`master`).
    По-друге, слід робити часті та невеликі коміти, а також регулярно оновлювати свою робочу гілку, інтегруючи останні зміни з основної гілки (`git pull` або `git rebase main`), щоб мінімізувати розбіжності.
    По-третє, злиття в основну гілку має відбуватися лише після рев'ю коду та через Pull/Merge Request, що дозволяє виявити та вирішити потенційні конфлікти до того, як вони потраплять у стабільну версію.
